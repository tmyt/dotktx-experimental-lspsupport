# DotKtx.Experimental.LspSupport

Experimental completion support for editing [DotKt](https://github.com/tmyt/dotkt)
projects with JetBrains' Kotlin language server.

The official language server cannot currently load DotKt's frontend KLIBs.
This package adds an incremental MSBuild target that:

1. waits for DotKt to generate its authoritative reference KLIB set;
2. projects those KLIB declarations into analysis-only Kotlin source;
3. supplies a JVM stdlib approximation plus a small `kotlin.clr` overlay JAR;
4. writes the generated sources below `.dotkt/lsp/stubs`; and
5. writes a `workspace.json` model understood by the language server's JSON
   workspace importer.

No Gradle project or Gradle wrapper is generated. `dotnet build` remains the
authority for compilation and diagnostics.

## Usage

Add the package as a private, build-only dependency:

```xml
<ItemGroup>
  <PackageReference
    Include="DotKtx.Experimental.LspSupport"
    Version="0.9.0"
    PrivateAssets="all"
    IncludeAssets="build" />
</ItemGroup>
```

Add the generated root model to `.gitignore`:

```gitignore
.dotkt/
workspace.json
```

Run the normal build once:

```bash
dotnet build
```

Then open the project directory in VS Code with the official **Kotlin by
JetBrains** extension. If the extension has a forced build tool setting, set
`intellij.buildTool` to `json` or return it to its automatic default.

## Generated files

```text
workspace.json             JetBrains LSP project model
.dotkt/
└─ lsp/
   ├─ .stamp               MSBuild incremental output
   ├─ README.md
   └─ stubs/               KLIB-derived Kotlin declarations
```

The package removes `.dotkt/**/*.kt` from DotKt's `@(KotlinCompile)` item so
the editor projection cannot enter the real CLR assembly. It refuses to
overwrite an existing `workspace.json` unless that file was generated by this
package.

The two analysis JARs are owned and shipped by this package. LspSupport does
not discover the compiler-host stdlib through DotKt.Toolchain's private package
layout at project build time.

Set `DotKtxExperimentalLspSupportEnabled` to `false` to disable generation.
`dotnet clean` removes the generated workspace when it is owned by this
package.

## Analysis model and known approximations

JetBrains LSP currently cannot consume DotKt's frontend stdlib KLIB directly.
The package therefore uses the matching JVM `kotlin-stdlib.jar` for the ordinary
Kotlin API surface and adds `dotkt-lsp-overlay.jar` for DotKt-only declarations:

- `ClrRef`, `byref`;
- `StackBuffer`, `Span`, `stackBuffer`; and
- `ClrEvent`, `clrEvent`, `EventSubscription`.

The overlay is deliberately hand-maintained while this package is experimental.
When `DotKtVersion` or `DotKtKotlinVersion` changes in `Directory.Build.props`,
compare it with DotKt's `libraries/stdlib/clr/kotlin/clr/CompilerIntrinsics.kt`
and `EventSubscription.kt`.

KLIB platform-flexible types such as `String!` cannot be represented in Kotlin
source. The generated model uses the non-null lower bound for completion.
JVM-only stdlib APIs can also appear in completion even when DotKt does not
implement them. The generated sources and both JARs are editor inputs only and
must not be used as DotKt compiler or runtime inputs.

## Development

```bash
./verify.sh
node tests/Smoke/verify-lsp.mjs
```

This packs the NuGet package, restores the smoke project against DotKt 0.9.8,
and verifies that an ordinary `dotnet build` generated `workspace.json`, the
analysis libraries, and a `System.Text.StringBuilder` completion declaration.
The Node verifier additionally starts an installed JetBrains Kotlin language
server and checks CLR-reference completion, DotKt overlay completion, member
completion, and go-to-definition end to end.
